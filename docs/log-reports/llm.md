# LLM Log Report Fields

## 1. Description

Defines the metadata and table fields in the HTML report generated by the logger `llm` view. Row values come from stored `LLMLogRecord` entries queried newest first and capped at 100 rows.

## 2. JSON Model

````json
{
  "report": {
    "title": "LLM Activity Logs",
    "source": "dev",
    "log_type": "llm",
    "generated_at": "2026-11-20T010203456789Z",
    "file_name": "2026-11-20T010203456789Z-llm.html",
    "row_count": 1,
    "rows": [
      {
        "id": "log-1",
        "created": "2026-11-19 10:00:01",
        "status": "Success",
        "step_id": "step-1",
        "provider": "ollama",
        "model": "llama3.1",
        "done_reason": "stop",
        "input_tokens": 128,
        "output_tokens": 42,
        "total_tokens": 170,
        "duration_s": "2.500",
        "start_memory_mb": "10.5",
        "peak_memory_mb": "20.5",
        "end_memory_mb": "12.5",
        "memory_delta_mb": "2.0",
        "cpu_avg_percent": "4.5",
        "cpu_peak_percent": "9.0",
        "samples": 3,
        "error": "-"
      }
    ]
  }
}
````

## 3. Data Fields

### Metadata

| Name | Type | Required | Nullable | Source | Calculation | Description | Constraints |
| --- | --- | --- | --- | --- | --- | --- | --- |
| title | string | Yes | No | `ReportTable.title` | Fixed by the report builder | Report heading | `LLM Activity Logs` |
| source | string | Yes | No | `LoggerCLIDependencies.source` | Selected log database | Output subfolder name | `dev`, `e2e`, or `test` |
| log_type | string | Yes | No | `llm` command | Fixed by the selected view | Filename report type | `llm` |
| generated_at | datetime | Yes | No | Report generation time | UTC timestamp | Filename timestamp | `YYYY-MM-DDTHHMMSSffffffZ` |
| file_name | string | Yes | No | `generated_at` and `log_type` | `<generated_at>-<log_type>.html` | Generated file name | Written under `./logs/<source>/` |
| row_count | integer | Yes | No | `rows` | Count of returned records | Number of table rows | 0–100 |
| rows | array[object] | Yes | No | Query results | Normalized rows for display | Table row objects | 0–100; see Columns |

### Columns

| Name | Type | Required | Nullable | Source | Calculation | Description | Constraints |
| --- | --- | --- | --- | --- | --- | --- | --- |
| id | string | Yes | No | `LLMLogRecord.id` | None | Log record ID | UUID |
| created | string | Yes | No | `LLMLogRecord.created_at` | `isoformat(sep=" ")` | Time the log was created | UTC, no suffix |
| status | string | Yes | No | `LLMLogRecord.status` | `SUCCESS`, `FAILED`, `TIMEOUT` → `Success`, `Failed`, `Timeout` | Call outcome | Unknown values show `Unknown` |
| step_id | string | No | Yes | `LLMLogRecord.processing_step_id` | None | Linked processing step | `null` shows `-` |
| provider | string | Yes | No | `LLMLogRecord.provider` | None | LLM provider name | Non-empty string |
| model | string | Yes | No | `LLMLogRecord.model` | None | LLM model name | Non-empty string |
| done_reason | string | No | Yes | `LLMResponseLog.finish_reason` | None | Provider completion reason | `null` shows `-` |
| input_tokens | integer | No | Yes | `LLMUsageLog.input_tokens` | None | Prompt token count | `null` shows `-` |
| output_tokens | integer | No | Yes | `LLMUsageLog.output_tokens` | None | Response token count | `null` shows `-` |
| total_tokens | integer | No | Yes | `LLMUsageLog.total_tokens` | `input_tokens + output_tokens` when both exist | Combined token count | Missing component shows `-` |
| duration_s | string | No | Yes | `LogPerformance.duration_ms` | `duration_ms / 1000` | Call duration | 3 decimals; `null` shows `-` |
| start_memory_mb | string | No | Yes | `LogPerformance.start_memory_mb` | Format to 1 decimal | RSS at start | `null` shows `-` |
| peak_memory_mb | string | No | Yes | `LogPerformance.peak_memory_mb` | `max(start, end, samples)` | Highest sampled RSS | 1 decimal; `null` shows `-` |
| end_memory_mb | string | No | Yes | `LogPerformance.end_memory_mb` | Format to 1 decimal | RSS at end | `null` shows `-` |
| memory_delta_mb | string | No | Yes | `LogPerformance.memory_delta_mb` | `end - start` | RSS change | May be negative; `null` shows `-` |
| cpu_avg_percent | string | No | Yes | `LogPerformance.cpu_avg_percent` | Mean of valid CPU samples | Average CPU usage | 1 decimal; `null` shows `-` |
| cpu_peak_percent | string | No | Yes | `LogPerformance.cpu_peak_percent` | `max(valid CPU samples)` | Peak CPU usage | 1 decimal; `null` shows `-` |
| samples | integer | Yes | No | `LogPerformance.sample_count` | Count of valid CPU samples | Number of CPU samples | Minimum `0` |
| error | string | No | Yes | `LogError.type` and `LogError.message` | `type: message`, or `type`, or `Error: message` | Error summary | No error shows `-` |

## 4. Validation

- Values are HTML-escaped before rendering.
- Empty results produce a row with `No records found.`.
- Each report contains at most 100 rows.
- Query failures report an error in the CLI and do not create a report.
- Browser-open failures print a warning and preserve the report path.
