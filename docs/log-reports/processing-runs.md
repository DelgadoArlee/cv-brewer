# Processing Run Report Fields

## 1. Description

Defines the metadata and table fields in the HTML report generated by `resume-upload > view runs`. Row values come from stored `ProcessingRunRecord` entries queried newest first and capped at 100 rows.

## 2. JSON Model

````json
{
  "report": {
    "title": "Processing Runs",
    "source": "dev",
    "log_type": "processing-runs",
    "generated_at": "2026-11-20T010203456789Z",
    "file_name": "2026-11-20T010203456789Z-processing-runs.html",
    "row_count": 1,
    "rows": [
      {
        "id": "run-1",
        "started": "2026-11-20 10:00:00",
        "status": "Success",
        "result": "stored",
        "resume_id": "resume-1",
        "matched_resume_id": null,
        "steps": "8/8 (0 failed, 0 skipped)",
        "duration_s": "1.000",
        "start_memory_mb": "100.5",
        "peak_memory_mb": "200.5",
        "end_memory_mb": "120.5",
        "memory_delta_mb": "20.0",
        "cpu_avg_percent": "12.5",
        "cpu_peak_percent": "25.5",
        "samples": 5,
        "error": "-"
      }
    ]
  }
}
````

## 3. Data Fields

### Metadata

| Name | Type | Required | Nullable | Source | Calculation | Description | Constraints |
| --- | --- | --- | --- | --- | --- | --- | --- |
| title | string | Yes | No | `ReportTable.title` | Fixed by the report builder | Report heading | `Processing Runs` |
| source | string | Yes | No | `LoggerCLIDependencies.source` | Selected log database | Output subfolder name | `dev`, `e2e`, or `test` |
| log_type | string | Yes | No | `processing-runs` command | Fixed by the selected view | Filename report type | `processing-runs` |
| generated_at | datetime | Yes | No | Report generation time | UTC timestamp | Filename timestamp | `YYYY-MM-DDTHHMMSSffffffZ` |
| file_name | string | Yes | No | `generated_at` and `log_type` | `<generated_at>-<log_type>.html` | Generated file name | Written under `./logs/<source>/` |
| row_count | integer | Yes | No | `rows` | Count of returned records | Number of table rows | 0–100 |
| rows | array[object] | Yes | No | Query results | Normalized rows for display | Table row objects | 0–100; see Columns |

### Columns

| Name | Type | Required | Nullable | Source | Calculation | Description | Constraints |
| --- | --- | --- | --- | --- | --- | --- | --- |
| id | string | Yes | No | `ProcessingRunRecord.run_id` | None | Run ID | UUID |
| started | string | Yes | No | `ProcessingRunRecord.started_at` | `isoformat(sep=" ")` | Run start time | UTC, no suffix |
| status | string | Yes | No | `ProcessingRunRecord.status` | Status enum → display label | Final run status | Unknown values show `Unknown` |
| result | string | No | Yes | `ProcessingRunRecord.result` | None | Final processing outcome | `null` shows `-` |
| resume_id | string | No | Yes | `ProcessingRunRecord.resume_id` | None | Saved resume ID | `null` shows `-` |
| matched_resume_id | string | No | Yes | `ProcessingRunRecord.matched_resume_id` | None | Duplicate match ID | `null` shows `-` |
| steps | string | Yes | No | `ProcessingRunRecord.summary` | `completed/total (failed failed, skipped skipped)` | Aggregated step counts | Missing summary values default to `0` |
| duration_s | string | No | Yes | `ProcessingRunRecord.duration_ms` | `duration_ms / 1000` | Total run duration | 3 decimals; `null` shows `-` |
| start_memory_mb | string | No | Yes | `ProcessingPerformance.start_memory_mb` | Format to 1 decimal | RSS at start | `null` shows `-` |
| peak_memory_mb | string | No | Yes | `ProcessingPerformance.peak_memory_mb` | `max(start, end, samples)` | Highest sampled RSS | 1 decimal; `null` shows `-` |
| end_memory_mb | string | No | Yes | `ProcessingPerformance.end_memory_mb` | Format to 1 decimal | RSS at end | `null` shows `-` |
| memory_delta_mb | string | No | Yes | `ProcessingPerformance.memory_delta_mb` | `end - start` | RSS change | May be negative; `null` shows `-` |
| cpu_avg_percent | string | No | Yes | `ProcessingPerformance.cpu_avg_percent` | Mean of valid CPU samples | Average CPU usage | 1 decimal; `null` shows `-` |
| cpu_peak_percent | string | No | Yes | `ProcessingPerformance.cpu_peak_percent` | `max(valid CPU samples)` | Peak CPU usage | 1 decimal; `null` shows `-` |
| samples | integer | Yes | No | `ProcessingPerformance.sample_count` | Count of valid CPU samples | Number of CPU samples | Minimum `0` |
| error | string | No | Yes | `ProcessingError.code`, `.type`, `.message` | `code or type or Error`, then `: message` | First run error summary | No error shows `-` |

## 4. Validation

- Values are HTML-escaped before rendering.
- Empty results produce a row with `No records found.`.
- Each report contains at most 100 rows.
- Query failures report an error in the CLI and do not create a report.
- Browser-open failures print a warning and preserve the report path.
