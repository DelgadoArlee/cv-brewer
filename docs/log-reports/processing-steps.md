# Processing Step Report Fields

## 1. Description

Defines the metadata and table fields in the HTML report generated by `resume-upload > view steps`. Rows come from stored `ProcessingStepRecord` entries for the selected run, queried newest first and capped at 100 rows.

## 2. JSON Model

````json
{
  "report": {
    "title": "Processing Steps - run-1",
    "source": "dev",
    "log_type": "processing-steps-run-1",
    "generated_at": "2026-11-20T010203456789Z",
    "file_name": "2026-11-20T010203456789Z-processing-steps-run-1.html",
    "row_count": 1,
    "rows": [
      {
        "id": "step-1",
        "step": "parsing",
        "order": 6,
        "attempt": 1,
        "started": "2026-11-20 10:00:02",
        "status": "Success",
        "duration_s": "1.000",
        "start_memory_mb": "1.5",
        "peak_memory_mb": "2.5",
        "end_memory_mb": "1.8",
        "memory_delta_mb": "0.3",
        "cpu_avg_percent": "1.2",
        "cpu_peak_percent": "2.4",
        "samples": 2,
        "error": "-",
        "metadata": "{'file_name': 'resume.pdf'}"
      }
    ]
  }
}
````

## 3. Data Fields

### Metadata

| Name | Type | Required | Nullable | Source | Calculation | Description | Constraints |
| --- | --- | --- | --- | --- | --- | --- | --- |
| title | string | Yes | No | Selected run ID | `Processing Steps - <run_id>` | Report heading | `Processing Steps - none` when no runs exist |
| source | string | Yes | No | `LoggerCLIDependencies.source` | Selected log database | Output subfolder name | `dev`, `e2e`, or `test` |
| log_type | string | Yes | No | Selected run ID | `processing-steps-<run_id>` | Filename report type | Run ID lowercased; non-alphanumeric runs become `-` |
| generated_at | datetime | Yes | No | Report generation time | UTC timestamp | Filename timestamp | `YYYY-MM-DDTHHMMSSffffffZ` |
| file_name | string | Yes | No | `generated_at` and `log_type` | `<generated_at>-<log_type>.html` | Generated file name | Written under `./logs/<source>/` |
| row_count | integer | Yes | No | `rows` | Count of returned steps | Number of table rows | 0–100 |
| rows | array[object] | Yes | No | Query results | Normalized rows for display | Table row objects | 0–100; see Columns |

### Columns

| Name | Type | Required | Nullable | Source | Calculation | Description | Constraints |
| --- | --- | --- | --- | --- | --- | --- | --- |
| id | string | Yes | No | `ProcessingStepRecord.step_id` | None | Step ID | UUID |
| step | string | Yes | No | `ProcessingStepRecord.step_name` | None | Processing stage name | Non-empty string |
| order | integer | Yes | No | `ProcessingStepRecord.step_order` | `str(value)` | Stage order | Non-negative integer |
| attempt | integer | Yes | No | `ProcessingStepRecord.attempt_number` | `str(value)` | Attempt number | Starts at `1` |
| started | string | Yes | No | `ProcessingStepRecord.started_at` | `isoformat(sep=" ")` | Step start time | UTC, no suffix |
| status | string | Yes | No | `ProcessingStepRecord.status` | Status enum → display label | Final step status | Unknown values show `Unknown` |
| duration_s | string | No | Yes | `ProcessingStepRecord.duration_ms` | `duration_ms / 1000` | Step duration | 3 decimals; skipped steps show `0.000` |
| start_memory_mb | string | No | Yes | `ProcessingPerformance.start_memory_mb` | Format to 1 decimal | RSS at step start | `null` shows `-` |
| peak_memory_mb | string | No | Yes | `ProcessingPerformance.peak_memory_mb` | `max(start, end, step-window samples)` | Highest step RSS | 1 decimal; `null` shows `-` |
| end_memory_mb | string | No | Yes | `ProcessingPerformance.end_memory_mb` | Format to 1 decimal | RSS at step end | `null` shows `-` |
| memory_delta_mb | string | No | Yes | `ProcessingPerformance.memory_delta_mb` | `end - start` | Step RSS change | May be negative; `null` shows `-` |
| cpu_avg_percent | string | No | Yes | `ProcessingPerformance.cpu_avg_percent` | Mean of step-window CPU samples | Average CPU usage | 1 decimal; `null` shows `-` |
| cpu_peak_percent | string | No | Yes | `ProcessingPerformance.cpu_peak_percent` | `max(step-window CPU samples)` | Peak CPU usage | 1 decimal; `null` shows `-` |
| samples | integer | Yes | No | `ProcessingPerformance.sample_count` | Count of step-window CPU samples | Number of CPU samples | Minimum `0` |
| error | string | No | Yes | `ProcessingError.code`, `.type`, `.message` | `code or type or Error`, then `: message` | Step error summary | No error shows `-` |
| metadata | string | No | Yes | `ProcessingStepRecord.metadata` | `str(dict)` when present | Step context | Empty object shows `-` |

## 4. Validation

- Values are HTML-escaped before rendering.
- Empty results produce a row with `No records found.`.
- Each report contains at most 100 steps for the selected run.
- Query failures report an error in the CLI and do not create a report.
- Browser-open failures print a warning and preserve the report path.
