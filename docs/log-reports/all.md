# All Logs Report Fields

## 1. Description

Defines the metadata and table fields in the HTML report generated by the logger `all` view. Rows are normalized LLM log and processing run records, merged newest first and capped at 100. Processing steps are not included.

## 2. JSON Model

````json
{
  "report": {
    "title": "All Logs",
    "source": "dev",
    "log_type": "all",
    "generated_at": "2026-11-20T010203456789Z",
    "file_name": "2026-11-20T010203456789Z-all.html",
    "row_count": 1,
    "rows": [
      {
        "source": "Run",
        "id": "run-1",
        "timestamp": "2026-11-20 10:00:00",
        "status": "Success",
        "summary": "resume_processing v1.0",
        "details": "result=stored; resume=resume-1; steps=8/8",
        "start_memory_mb": "100.5",
        "peak_memory_mb": "200.5",
        "end_memory_mb": "120.5",
        "memory_delta_mb": "20.0",
        "cpu_avg_percent": "12.5",
        "cpu_peak_percent": "25.5",
        "samples": 5,
        "error": "-"
      }
    ]
  }
}
````

## 3. Data Fields

### Metadata

| Name | Type | Required | Nullable | Source | Calculation | Description | Constraints |
| --- | --- | --- | --- | --- | --- | --- | --- |
| title | string | Yes | No | `ReportTable.title` | Fixed by the report builder | Report heading | `All Logs` |
| source | string | Yes | No | `LoggerCLIDependencies.source` | Selected log database | Output subfolder name | `dev`, `e2e`, or `test` |
| log_type | string | Yes | No | `all` command | Fixed by the selected view | Filename report type | `all` |
| generated_at | datetime | Yes | No | Report generation time | UTC timestamp | Filename timestamp | `YYYY-MM-DDTHHMMSSffffffZ` |
| file_name | string | Yes | No | `generated_at` and `log_type` | `<generated_at>-<log_type>.html` | Generated file name | Written under `./logs/<source>/` |
| row_count | integer | Yes | No | `rows` | Count of merged records | Number of table rows | 0–100 |
| rows | array[object] | Yes | No | Query results | Normalized rows for display | Table row objects | 0–100; see Columns |

### Columns

| Name | Type | Required | Nullable | Source | Calculation | Description | Constraints |
| --- | --- | --- | --- | --- | --- | --- | --- |
| source | string | Yes | No | `LogOverviewRecord.source` | Normalizer sets `LLM` or `Run` | Origin of the row | Fixed labels |
| id | string | Yes | No | `LLMLogRecord.id` or `ProcessingRunRecord.run_id` | None | Source record ID | UUID |
| timestamp | string | Yes | No | `created_at` or `started_at` | `isoformat(sep=" ")` | Record time and merge key | Newest first |
| status | string | Yes | No | Source record status | Status enum → display label | Record status | Unknown values show `Unknown` |
| summary | string | Yes | No | LLM operation or run process/version | Run value is `<process_name> v<process_version>` | Short record description | Non-empty string |
| details | string | Yes | No | LLM usage or run summary | Formatted provider/model/step or result/resume/steps | Extra context | Missing parts show `-` |
| start_memory_mb | string | No | Yes | `LogOverviewRecord.performance` | Format to 1 decimal | RSS at start | `null` shows `-` |
| peak_memory_mb | string | No | Yes | `LogOverviewRecord.performance` | `max(start, end, samples)` | Highest sampled RSS | 1 decimal; `null` shows `-` |
| end_memory_mb | string | No | Yes | `LogOverviewRecord.performance` | Format to 1 decimal | RSS at end | `null` shows `-` |
| memory_delta_mb | string | No | Yes | `LogOverviewRecord.performance` | `end - start` | RSS change | May be negative; `null` shows `-` |
| cpu_avg_percent | string | No | Yes | `LogOverviewRecord.performance` | Mean of valid CPU samples | Average CPU usage | 1 decimal; `null` shows `-` |
| cpu_peak_percent | string | No | Yes | `LogOverviewRecord.performance` | `max(valid CPU samples)` | Peak CPU usage | 1 decimal; `null` shows `-` |
| samples | integer | Yes | No | `LogOverviewRecord.performance` | Count of valid CPU samples | Number of CPU samples | Minimum `0` |
| error | string | Yes | No | `LogOverviewRecord.error` | Type/code label plus message | Error summary | No error shows `-` |

## 4. Validation

- LLM logs and processing runs are merged by timestamp, newest first.
- Processing steps are not included.
- Values are HTML-escaped; empty results show `No records found.`.
- The merged report contains at most 100 rows.
- Query failures report an error in the CLI and do not create a report.
